# 文档说明

本文档定义“观鱼记”第一阶段可独立交付的 Android 本地版。所有鱼缸、鱼只、照片引用、喂食、换水、水质、成长、提醒与统计数据均保存在用户手机中。第一阶段不建设业务后端、不要求注册登录、不做云端同步。

本文档既是产品设计说明，也是 UI 实现与开发验收依据。视觉稿中的数据仅为示例，实际界面必须展示用户真实录入的数据；不得用示例数值伪装成真实水质或真实记录。

# 1. 产品范围与设计原则

## 1.1 产品目标

为观赏鱼爱好者提供一个离线可用的个人养鱼记录工具。每个鱼缸独立管理，每条鱼拥有专属照片与档案，用户可以记录鱼只成长、每天喂食、鱼缸水质、换水和日常养护，并通过本地通知获得计划提醒。

## 1.2 第一阶段包含

- 鱼缸管理：创建、编辑、归档、查看详情；支持淡水缸和海水缸。
- 鱼只管理：添加照片、名字、鱼种、所属鱼缸、入缸日期、状态与备注。
- 成长记录：体长、体重、测量时间、照片和备注；展示真实测量趋势。
- 喂食记录：支持全缸或指定鱼只，记录时间、饲料、数量和摄食情况。
- 水质记录：温度、pH、氨/铵、亚硝酸盐、硝酸盐；海水缸可记录盐度、比重、碱度。
- 换水记录：时间、换水量、可选比例、备注与下一次计划。
- 养护任务：喂食、换水、水质检测、盐度检测、设备维护和自定义任务。
- 本地统计、提醒中心、单位设置、数据导出与恢复。
## 1.3 第一阶段不包含

- 账号注册、登录、云数据库、自动跨设备同步。
- 云端 AI 识鱼、云端问答、订阅付费、社交和多人共享。
- 传感器自动采集与设备远程控制。
- 医疗诊断或自动生成确定性的疾病结论。
## 1.4 核心设计原则

- 本地优先：断网时所有核心记录和查询功能仍可使用。
- 鱼只与鱼缸分离建档：一条鱼关联当前鱼缸，但历史事件保留原始归属。
- 计划与事实分离：计划任务不等于已执行记录。
- 缺失不等于零：未测量的水质、未知体长不能以 0 显示。
- 真实数据优先：展示数值时标注测量时间、单位与数据来源。
- 安全操作可恢复：归档优先于永久删除；高风险操作需二次确认。
# 2. 导航结构与全局交互

底部采用五个一级入口，页面内的新增、编辑和详情通过卡片与操作按钮进入。

| --- | --- | --- |
| 一级导航 | 页面内容 | 常用操作 |
| 总览 | 鱼缸概况、今日任务、最近水质、最近关注的鱼 | 新增鱼缸、快速喂食、记录水质 |
| 我的鱼 | 鱼只列表、搜索、筛选、排序 | 添加鱼、打开鱼只详情 |
| 鱼缸 | 鱼缸列表、淡水/海水筛选 | 添加鱼缸、打开鱼缸详情 |
| 养护 | 今日任务、日历、养护历史 | 完成、延期、跳过、补录 |
| 我的 | 统计、设置、备份恢复、关于 | 导出数据、调整单位和通知 |

## 2.1 全局导航规则

- 从鱼缸详情添加鱼时，新增鱼表单自动预选该鱼缸。
- 从单鱼详情记录喂食时，自动选择该鱼作为喂食对象。
- 从鱼缸详情记录水质或换水时，自动关联当前鱼缸。
- 返回操作保留列表滚动位置、搜索关键词和筛选条件。
- 表单未保存且内容已修改时，返回需提示“放弃更改 / 继续编辑”。
- 保存成功后返回来源页面，并立即更新相关摘要，不要求用户手动刷新。
# 3. 视觉与组件规范

## 3.0 界面视觉基线

首期位图设计稿（`UI设计总览图.png`、`鱼缸卡片设计规范展示板.png`）已于 2026-10-18 移除，避免与当前实现持续漂移。当前视觉基线以 [实机截图文档](../实机截图.md) 和本章 3.1、3.1.1 的可执行参数为准；实现细节以 `ui/theme/AquariumCardTokens.kt`、`core/designsystem/` 代码为唯一事实源。历史位图可在 Git 历史中查看。

## 3.1 视觉方向

采用干净、自然、现代的水族风格：浅色背景、蓝色主色、青绿色辅助色、真实鱼类照片、适度留白和清晰的信息层级。避免大面积装饰性渐变、重玻璃拟态和过多装饰，确保数据可读性优先。

卡片视觉以 3.1.1 的分层参数与 `ui/theme/AquariumCardTokens.kt` 为准。列表卡片的立体感由低透明度分层光影实现（见 3.1.1），不使用真实高斯模糊与大面积彩色光斑。

| --- | --- |
| 项目 | 规范建议 |
| 主色 | 水蓝色/海洋蓝，用于主按钮、选中态和关键链接 |
| 辅助色 | 青绿色，用于已完成状态和辅助强调；异常状态同时配图标与文字 |
| 背景 | 浅灰白；卡片白色，边框低对比度 |
| 圆角 | 卡片 12–16dp；按钮 10–14dp；头像/鱼图按内容选择 |
| 间距 | 采用 4dp 倍数间距；页面左右边距建议 16dp |
| 触控 | 主要触控区域建议不小于 48dp |
| 照片 | 鱼只卡片统一裁切比例；详情页允许大图查看；保留原图与缩略图策略 |
| 字体 | 标题、关键数值、正文、辅助信息分级；单位不可与数值混淆 |

### 3.1.1 卡片立体规范（鱼只卡片 / 鱼缸卡片）

「我的鱼」与「鱼缸」列表共用同一卡片外壳，立体效果必须两处一致。实现依据为 `core/designsystem/CardDepthDecoration.kt` + `ui/theme/AquariumCardTokens.kt`，参数以本节为准。

**分层结构（由外到内）**

| 层 | 内容 | 关键参数 |
| --- | --- | --- |
| L1 外发光 | 主题色冷光晕，透出深色投影之外（API 28+ 生效） | 高度 14dp，环境光 α0.08、点光 α0.15 |
| L2 接地投影 | 系统 elevation 阴影，按下时收紧 | 静置 8dp / 按下 2dp，环境光 α0.34、点光 α0.40 |
| L2b 接触阴影 | 自绘暗带，向下偏移并向外逐层变淡 | 6 层，每层外扩 0.5dp、下偏 1dp、单层 α0.036 |
| L3 卡面 | 深蓝竖向渐变 | `#0D3355 → #0A1F35` |
| L4 照片层 | 4:3 裁切照片 + 顶部 scrim + **下沿暗带** | 暗带高 18dp、α0.42 |
| L5 外缘受光描边 | 左上亮白 → 中段主题色 → 右下压深；外侧再垫一圈宽低透明光晕，上缘叠一道两端渐隐的镜面反光 | 实线 1.35dp、α0.68（静置）/1.0（按下）；光晕 3.2dp、α0.28；反光 α0.55 |
| L6 内斜面 | 内缩一圈的细亮边，表现玻璃切面厚度 | 宽 1dp、内缩 2.25dp |
| L7 底部反光边 | 贴底淡蓝亮线，避开圆角 | 距底 1.6dp，宽 0.9dp，α0.45 |
| L8 信息面板 | 面板渐变 + **顶部内阴影**（压在内容之下）+ 1dp 交界高光 | 内阴影高 6dp、α0.35；高光 α0.55 |

**交互**

- 按下：沿底边后仰 3°（`rotationX`，`cameraDistance = 12 × density`）、缩放 0.972、投影 8dp→2dp、描边提亮，全部 160ms 收敛。
- 拖起（长按排序）：直立（倾斜归零）、放大 1.045、投影 22dp、描边提亮——"拿起"与"按下"必须是相反的观感，两者互斥。
- 抬起：弹性回位；入场动画（透明度 + 16dp 位移）保持不变。

**约束**

- 不使用 `Modifier.blur` / `RenderEffect`：真实模糊需 API 31，而 minSdk 为 26，低版本会直接丢失厚度。立体感只能由低透明度渐变与细描边叠加得到。
- 着色阴影需 API 28+；API 26–27 自动退化为单层深色投影，效果可接受但不含冷光晕。
- 卡片只使用真实业务字段与真实状态（在养 / 隔离 / 已转出 / 已故 / 已归档），**禁止**搬用设计板中的 SSR / SR / R 等级徽章与任何虚构稀有度。
- 卡面文字保持白色系（主 `#FFFFFF`、次 `#A8C5DE`）；设计板参数区标注的深色文字色值适用于浅色卡面，不适用于本项目深色卡面。
- 自绘部分必须在 `drawWithCache` 内构建画笔，按压动画之外不逐帧重绘，保证列表滚动性能。

# 4. 页面详细设计与交互逻辑

每个页面均需实现：正常状态、空状态、加载/处理中状态、错误状态。纯本地查询通常不需要长时间加载动画，但保存、导入、图片处理等耗时操作需要显示处理中状态。

## 4.1 首次启动 / 引导页

页面目标：让用户理解本地存储方式并快速创建第一个鱼缸。

### 布局与交互

- 品牌与简短说明；“开始使用”主按钮；可选的隐私说明入口。
- 首次进入不强制注册，不请求与核心功能无关的权限。
- 点击开始使用进入创建鱼缸流程；若用户中途退出，下次仍可继续。
- 相册/通知权限在用户实际使用对应功能时再请求。
### 边界与异常

- 无网络也能使用；首次启动没有任何示例鱼只或虚假水质。
## 4.2 首页总览

页面目标：快速回答：我有几个鱼缸、今天要做什么、最近水质如何。

### 布局与交互

- 顶部显示日期、问候语、通知入口和未读提醒数。
- 鱼缸概览横向卡片显示照片、名称、淡水/海水标签、鱼只数量和待办数。
- 今日任务按时间排序，展示所属鱼缸与完成状态；可快速完成或跳转记录表单。
- 水质摘要显示最近测量值、单位和测量时间；过期数据标注需要复测。
- 最近关注的鱼展示照片、名字、入缸时长和最近体长。
- 提供快捷入口：添加鱼缸、添加鱼、记录喂食、记录水质。
### 边界与异常

- 无鱼缸：显示创建第一个鱼缸的引导。
- 无任务：显示“今天暂无计划任务”，同时保留新增任务入口。
- 无水质记录：显示“尚无测量数据”，不可显示默认正常值。
- 任务完成后首页立即更新，避免重复点击导致重复记录。
## 4.3 我的鱼列表

页面目标：快速查找和管理所有鱼只。

### 布局与交互

- 顶部标题、搜索框、筛选和排序入口；右下或右上提供新增鱼按钮。
- 筛选：全部、按鱼缸、按鱼种、在养、隔离、已转出、已故。
- 排序：最近添加、入缸时间、存活记录天数、最近测量时间、自定义顺序。
- 卡片展示鱼照片、名字、鱼种、所属缸、入缸天数、最近体长、今日喂食摘要。
- 点击卡片进入鱼只详情；编辑走卡片右上角按钮；**长按卡片进入拖动排序**（见 4.17 拖拽排序）。
### 边界与异常

- 搜索无结果显示清除搜索；空列表提供添加鱼入口。
- 已故/转出鱼只保留在历史筛选中，不继续参与当前在养数量。
## 4.4 添加/编辑鱼只

页面目标：建立单鱼档案，避免一次性录入过多信息。

### 布局与交互

- 字段：照片、名称（必填）、鱼种（可选）、所属鱼缸（必填）、入缸日期（必填）、出生日期（可选）、体长/体重（可选）、性别、来源、备注。
- 照片支持相机或系统照片选择器；用户取消选择不影响其他表单字段。
- 选择所属鱼缸后显示该缸类型，便于用户核对环境。
- 填写初始体长/体重时，保存鱼只同时创建第一条成长记录。
- 点击保存后校验字段，成功进入鱼只详情。
### 边界与异常

- 名称去除首尾空格；入缸日期不能晚于今天，计划入缸应使用独立功能或状态。
- 体长/体重未填写时保持为空，不转换为 0。
- 保存失败时保留输入，显示可理解的错误原因。
## 4.5 鱼只详情

页面目标：单鱼的核心档案、统计和所有历史事件入口。

### 布局与交互

- 头部展示大图、鱼名、鱼种、当前鱼缸和状态；照片点击放大。
- 指标卡展示入缸时长、最近体长、今日喂食摘要、成长记录数。
- 标签页：概览、成长、喂食、时间线。
- 快捷操作：记录喂食、记录体长、添加照片、健康观察、编辑档案。
- 更多菜单：转缸、标记已转出、标记已故、归档。
- 转缸操作记录转缸日期和目标鱼缸，不改写旧事件的历史归属。
### 边界与异常

- 已故鱼只显示确认的状态日期与历史，不再生成未来喂食任务。
- 没有成长记录时显示添加记录引导；不显示虚构曲线。
## 4.6 成长记录

页面目标：记录可追踪的体长、体重和外观变化。

### 布局与交互

- 新增字段：测量时间、体长、体重、单位、测量方式、照片、备注。
- 详情顶部显示最近一次测量数值与日期。
- 趋势图仅使用真实测量点；切换 30 天、90 天、全部等范围。
- 记录列表按测量时间倒序；支持查看、编辑和更正。
- 新增照片可以单独记录，也可关联一次测量。
### 边界与异常

- 只有一条测量记录时展示单点和提示，不绘制误导性趋势。
- 更正历史记录后重新计算曲线与摘要。
## 4.7 鱼缸列表

页面目标：管理多个独立鱼缸。

### 布局与交互

- 鱼缸卡片展示照片、名称、类型、容量、在养鱼数、最近换水、最近水质检测。
- 筛选全部、淡水缸、海水缸；支持名称搜索。
- 新增按钮进入创建鱼缸；点击卡片进入鱼缸详情。
- 长按卡片可拖动调整顺序（与「我的鱼」一致的交互，见 4.17 拖拽排序）。
- 归档鱼缸前检查是否仍有关联在养鱼只，并提示处理方式。
### 边界与异常

- 没有鱼缸时展示创建入口；没有水质记录时展示空值，不默认正常。
## 4.8 创建/编辑鱼缸

页面目标：设置鱼缸基本信息、系统类型和养护配置。

### 布局与交互

- 字段：名称、照片、类型（淡水/海水）、长宽高、实际水体容量、启用日期、过滤/加热/照明/造流设备、备注。
- 类型切换时更新水质指标模板和盐度相关提醒选项。
- 容量可以手动填写；若根据尺寸估算，需标注为估算值，并允许输入实际水体容量覆盖。
- 保存后进入鱼缸详情。
### 边界与异常

- 已有鱼只时切换淡水/海水类型，必须二次确认并提醒检查鱼只适配性。
- 切换类型不删除旧测量记录；旧记录保留当时参数和单位。
## 4.9 鱼缸详情

页面目标：集中查看鱼缸中的鱼、环境与养护历史。

### 布局与交互

- 顶部展示鱼缸照片、名称、类型、容量和在养数量。
- 标签页：概览、鱼只、水质、养护、统计。
- 快捷操作：添加鱼、记录水质、记录换水、添加养护任务。
- 概览展示最新环境摘要、下次任务和近期事件。
- 鱼只标签展示属于当前鱼缸的鱼卡片。
### 边界与异常

- 从该页进入新增记录时自动关联当前鱼缸。
- 鱼缸归档后不再产生未来任务，但历史数据可查询。
## 4.10 水质记录

页面目标：记录测量值并追踪变化。

### 布局与交互

- 记录时间；淡水/海水相关参数；每个参数保存数值、单位、测量方式和备注。
- 淡水默认可选温度、pH、氨/铵、亚硝酸盐、硝酸盐；海水额外提供盐度、比重、碱度等。
- 用户可配置目标范围；范围提示需要说明其来源或由用户设定。
- 保存后更新最近测量摘要并在图表中加入数据点。
- 历史记录可按参数和日期范围筛选。
### 边界与异常

- 空值不等于 0；盐度与比重是不同指标，不可直接比较。
- 超范围时提示复测/核对，不自动生成激进的加盐、换水等指令。
## 4.11 换水记录

页面目标：保存每次真实换水事件并安排下一次提醒。

### 布局与交互

- 字段：所属鱼缸、实际完成时间、换水量、可选换水比例、换水前后水温/盐度、用品、备注、下次计划日期。
- 若鱼缸实际水体容量已知，自动计算换水比例；容量未知时只保存换水量。
- 保存后新增换水历史、更新最近换水时间并重新安排未来任务。
- 历史列表展示日期、换水量、比例和备注。
### 边界与异常

- 计划日期与实际完成时间分开存储；补录历史不能覆盖原计划。
- 修改换水记录后重新计算关联统计。
## 4.12 喂食记录

页面目标：尽量少点几次就完成日常喂食记录。

### 布局与交互

- 快速模式默认当前时间和当前页面的鱼缸/鱼只；一键记录一次喂食。
- 完整模式：时间、鱼缸、对象（全缸/指定鱼/多条鱼）、饲料类型、投喂量、摄食结果和备注。
- 可创建常用饲料选项；自定义类型可重复使用。
- 保存后更新鱼缸喂食事件数和关联鱼只的喂食摘要。
- 支持补录、编辑和查看历史。
### 边界与异常

- 全缸一次喂食只计为一个鱼缸事件；关联多条鱼不能重复累计全缸次数。
- 用户取消保存时不生成记录；防止快速连点造成重复提交。
## 4.13 养护日历与任务

页面目标：管理一次性和重复性养护计划。

### 布局与交互

- 视图：今日列表、日历、未来计划、历史记录。
- 任务类型：喂食、换水、水质检测、盐度检测、设备维护、自定义。
- 每项任务展示计划时间、所属鱼缸、关联鱼只（可选）、状态。
- 操作：完成、延期、跳过、编辑、取消。
- 完成时根据任务类型进入对应记录表单或确认完成。
### 边界与异常

- 任务状态：待完成、已完成、已跳过、已逾期、已取消。
- 周期修改默认仅影响未来任务，不改写历史执行记录。
## 4.14 提醒中心与提醒设置

页面目标：让用户管理系统通知和任务规则。

### 布局与交互

- 提醒中心按待处理、已完成、已过期分类；点击提醒可进入关联任务或记录。
- 提醒设置可配置任务类型、时间、提前量、重复周期、所属鱼缸和启用状态。
- 盐度提醒仅对启用盐度管理的海水缸或用户明确启用盐度的鱼缸显示。
- 没有测量值时提醒“需要检测”；超出目标范围时显示测量值、单位、时间与目标范围。
- 系统通知权限被拒绝时提供设置入口，应用内任务仍可查看。
### 边界与异常

- 通知权限只在用户开启提醒时申请；不反复弹出系统权限请求。
- 更改时区、日期或重复规则后重算未来任务，避免重复通知。
## 4.15 统计报表

页面目标：帮助用户回顾养护规律与成长变化。

### 布局与交互

- 筛选鱼缸和时间范围；展示鱼只数量变化、喂食频率、换水频率/换水量、水质趋势和任务完成率。
- 单鱼详情展示该鱼的成长曲线；鱼缸详情展示该缸的环境趋势。
- 图表支持查看具体数据点、日期、单位和来源。
- 无足够数据时展示空状态和新增记录入口。
### 边界与异常

- 不把缺少记录的日期视为任务失败；不把存活天数转换为健康评分。
- 统计结果应可由原始记录复算。
## 4.16 我的与设置

页面目标：管理单位、通知、主题和数据备份。

### 布局与交互

- 设置项：温度、长度、体积、重量单位；日期格式；主题；通知开关；照片与存储管理；导出/恢复；帮助与反馈。
- 单位变化只影响展示和输入换算，不应悄悄改变原始记录含义。
- 数据导出生成带版本号的备份包；恢复前显示备份日期、内容概览和覆盖风险。
- 清空数据必须二次确认，并建议先导出备份。
### 边界与异常

- 导入失败不得清空现有数据；导入前先校验文件结构与版本。
- 备份包含数据库、照片文件和照片引用关系。

## 4.17 拖拽排序（我的鱼 / 鱼缸）

页面目标：让用户按自己的习惯排列卡片，而不是只能按系统预设排序。

### 布局与交互

- **长按卡片约 0.5 秒进入拖动**，拖动中卡片「被拿起」：直立、放大、投影拉长、描边提亮；松手落位即保存。
- 短按（不移动）仍然是进入详情，编辑仍走卡片右上角按钮。
- 拖到列表上/下边缘时自动滚动，支持跨行、跨列拖动。
- 起拖、落位各触发一次触觉反馈。
- 「我的鱼」新增排序项 **自定义顺序**：当前排序不是自定义顺序时，起拖会先切换到自定义顺序，并沿用用户当前看到的排列（列表不跳动），同时给出 Snackbar 提示。
- 选中的排序方式与自定义顺序一起保存，重启后保持。

### 边界与异常

- **搜索状态下不开放拖拽**：搜索结果是临时视图，"改了哪一条"说不清；此时长按不进入拖动。
- 带鱼缸/状态筛选时拖拽只重排**当前可见的卡片**，被筛掉的卡片相对位置保持不变。
- 新增的鱼只/鱼缸默认追加在自定义顺序末尾，不会打乱已排好的顺序。
- 顺序与排序方式存 `app_settings`（`list.order.fish` / `list.order.tank` / `list.sort.fish`），不新增数据库列，因而不影响既有备份的版本校验。
- 无障碍：每张卡片通过 TalkBack 自定义操作提供 **「上移」「下移」**，不依赖拖拽手势也能改顺序。
- 保存失败只在 Snackbar 提示，列表保持用户刚拖出来的顺序，不回滚。

# 5. 本地数据与文件存储设计

## 5.1 技术方案

建议 Kotlin + Jetpack Compose + Room/SQLite。Room 管理结构化记录，应用私有目录保存图片与备份临时文件；使用 Repository 层隔离 UI 与数据来源。第一阶段不需要网络 API 或服务器。

| --- | --- |
| 模块 | 建议实现 |
| UI | Jetpack Compose；页面状态由 ViewModel/StateFlow 管理 |
| 数据库 | Room + SQLite；外键、索引、事务和版本迁移 |
| 图片 | 系统 Photo Picker/相机；复制到应用私有目录并生成缩略图 |
| 提醒 | AlarmManager/WorkManager 按提醒精确性与系统限制选型；通知由本地生成 |
| 图表 | 基于真实历史记录绘制；显示单位、时间和空数据状态 |
| 备份 | 用户主动导出 ZIP/JSON + 图片；导入前校验与版本迁移 |

## 5.2 核心实体关系

- Tank 1:N Fish：鱼缸拥有多条鱼；Fish 保存当前 tankId。
- Fish 1:N GrowthRecord：一条鱼拥有多条成长测量记录。
- FeedingEvent 1:N FeedingTarget：一次喂食事件可以关联全缸或多条鱼，防止统计重复。
- Tank 1:N WaterTest；WaterTest 1:N WaterTestValue：一次检测有多个指标。
- Tank 1:N WaterChange：每次换水都是独立历史事件。
- Tank/Fish 1:N CareTask；CareTask 可关联 CareRecord：计划和实际执行分开。
## 5.3 建议数据表

| --- | --- | --- |
| 表 | 关键字段（示意） | 说明 |
| tanks | id, name, type, capacityValue, capacityUnit, startedAt, status, notes | 鱼缸基本信息 |
| fish | id, tankId, name, species, coverPhotoId, addedAt, birthDate, status, notes | 单鱼档案 |
| photos | id, localPath, thumbnailPath, mimeType, width, height, createdAt | 照片文件元数据 |
| growth_records | id, fishId, measuredAt, lengthValue/unit, weightValue/unit, method, photoId, notes | 成长测量 |
| feeding_events | id, tankId, fedAt, foodType, amountValue/unit, result, notes | 一次喂食事件 |
| feeding_targets | id, feedingEventId, fishId, targetType, result | 喂食关联对象 |
| water_tests | id, tankId, measuredAt, method, notes | 水质检测事件 |
| water_test_values | id, waterTestId, parameterCode, value, unit, targetMin, targetMax | 检测参数值 |
| water_changes | id, tankId, completedAt, volumeValue/unit, ratio, nextPlannedAt, notes | 换水历史 |
| care_tasks | id, tankId, fishId?, type, plannedAt, recurrenceRule, status | 养护计划 |
| care_records | id, taskId?, tankId, fishId?, type, completedAt, payloadJson, notes | 实际执行事件 |
| settings | key, value, updatedAt | 单位、主题和通知偏好 |

## 5.4 ID、时间和单位规则

- 所有实体使用稳定的 UUID 或等价唯一 ID，避免导入恢复时主键冲突。
- 存储时间建议统一保存为带时区语义的时间戳；展示时转换为设备本地时间。
- 日期类字段（如入缸日期）与精确时间字段（如喂食时间）区分处理。
- 数值字段与单位字段分开保存；空值保持 NULL，不用 0 表示未知。
- 枚举值采用稳定的代码，不把中文显示文案直接当作数据库逻辑值。
- 数据库增加索引：fish.tankId、growth_records.fishId+measuredAt、feeding_events.tankId+fedAt、water_tests.tankId+measuredAt、care_tasks.plannedAt+status。
## 5.5 照片管理

- 用户选择照片后，将文件复制到应用私有目录；数据库保存相对路径或文件 ID，不保存临时 URI 作为唯一引用。
- 鱼只封面和成长照片可以共用照片实体，避免同一文件重复保存。
- 照片删除前检查是否仍被鱼只封面或成长记录引用。
- 缩略图用于列表，原图用于详情预览；可提供压缩选项以节省空间。
- 导出备份时将图片文件与数据库一并打包，并保留引用关系。
# 6. 业务规则与提醒机制

## 6.1 入缸时长与存活记录

在养鱼的入缸时长 = 当前本地日期 − 入缸日期（产品显示可采用含首日的自然日口径，但全 App 必须统一）。标记已故后停止按当前日期增长，使用记录的状态日期作为终点。入缸时长不等于鱼的实际年龄；出生日期未知时不推算年龄。若用户不确定死亡日期，应允许记录“日期不详”。

## 6.2 换水比例

换水比例 = 换水量 ÷ 实际水体容量 × 100%。若容量未知，不显示比例；若容量是按尺寸估算的，明确标注估算值。

## 6.3 喂食统计

全缸喂食事件数按 feeding_events 去重统计；单鱼喂食摘要按 feeding_targets 的关联关系统计。一次事件关联 5 条鱼仍是 1 次鱼缸喂食，而不是 5 次。

## 6.4 任务状态机

| --- | --- | --- |
| 当前状态 | 用户操作 | 目标状态/结果 |
| 待完成 | 完成 | 已完成；写入实际记录和完成时间 |
| 待完成 | 延期 | 更新未来计划时间；保留变更信息 |
| 待完成 | 跳过 | 已跳过；可记录原因 |
| 待完成 | 超过计划时间 | 已逾期；允许继续完成或延期 |
| 任意未完成状态 | 取消 | 已取消；不再触发通知 |
| 已完成 | 编辑实际记录 | 更新记录；重新计算摘要，不重复创建事件 |

## 6.5 本地提醒执行

- 用户创建任务规则后，生成下一次计划实例并安排本地通知。
- 通知点击后打开对应任务或记录表单，而不是仅打开首页。
- 完成任务后取消当前通知，并安排下一次重复任务。
- 重复任务必须有稳定的规则 ID 与实例 ID，防止应用重启后重复创建。
- 设备重启、应用升级、时区变化后，按持久化规则重新安排未来任务。
- 系统通知不可用时，任务仍保留在 App 的今日列表。
- 应用卸载、系统限制或厂商省电策略可能影响通知送达；设置页应说明这是本地提醒，不承诺绝对准时。
## 6.6 盐度管理安全原则

- 盐度提醒只在用户启用该参数的鱼缸中显示。
- 无测量值只触发检测提醒，不判定盐度正常或异常。
- 目标范围可由用户配置，并显示最近测量值、单位和时间。
- 盐度与比重必须分别存储、分别展示。
- 首期只提供记录和复测提示，不根据单次异常值自动计算加盐或补水量。
# 7. 异常状态与数据安全

| --- | --- |
| 场景 | 预期行为 |
| 数据库写入失败 | 保留表单输入，提示失败原因；不得显示保存成功 |
| 用户取消照片选择 | 返回原表单，不清空其他字段 |
| 图片文件丢失 | 显示占位图并允许重新选择，不导致页面崩溃 |
| 日期输入错误 | 在字段附近提示并阻止保存 |
| 无水质数据 | 显示空状态与添加测量入口，不填默认值 |
| 重复点击保存 | 禁用提交按钮或使用幂等保护，避免重复记录 |
| 恢复备份版本不兼容 | 停止导入并解释原因，不改动现有数据 |
| 存储空间不足 | 提示清理空间或减少照片大小，保留已录入表单 |
| 通知权限关闭 | 保留应用内任务，提供前往系统设置的入口 |
| 归档含在养鱼只的鱼缸 | 提醒先转移鱼只或确认归档策略 |

## 7.1 数据备份策略

- 首期提供手动导出备份，不承诺云端自动备份。
- 备份包包含数据库导出、图片目录、版本信息和校验清单。
- 恢复前展示备份时间、鱼缸数、鱼只数和记录数。
- 默认先创建当前数据的安全备份，再执行恢复。
- 导入时使用事务或临时数据库验证，完整通过后再替换正式数据。
- 导出文件由用户自行保存；提醒用户备份文件也包含个人记录与照片。
# 8. 首期开发顺序

| --- | --- | --- |
| 迭代 | 开发内容 | 完成标准 |
| P0：基础骨架 | 导航、主题、Room、Repository、空状态组件 | 能运行；数据库迁移基础完成 |
| P1：鱼缸与鱼只 | 鱼缸 CRUD、鱼只 CRUD、照片管理、详情页 | 创建、编辑、归档、查询完整 |
| P2：成长与喂食 | 成长测量、照片时间线、喂食事件和关联对象 | 单鱼与全缸统计不重复 |
| P3：水质与换水 | 水质参数、历史图表、换水记录和比例 | 单位、空值和时间逻辑正确 |
| P4：任务与提醒 | 重复规则、本地通知、完成/延期/跳过 | 重启后可恢复未来任务，无重复任务 |
| P5：统计与备份 | 统计报表、导出、恢复、设置 | 恢复后照片引用与历史完整 |

# 9. 测试与验收标准

1. 首次启动无需注册或联网即可创建鱼缸。
1. 每条鱼有独立照片、名字、所属鱼缸和入缸日期。
1. 入缸时长根据日期计算；已故鱼只不再持续增加天数。
1. 成长记录按时间排序，体长曲线只使用真实测量值。
1. 全缸喂食一次即使关联多条鱼，鱼缸总事件数也只增加一次。
1. 淡水缸和海水缸显示适用的参数模板；历史数据不因类型切换被删除。
1. 换水量、实际完成时间和计划时间分开保存。
1. 没有盐度数据时提示检测，不显示假定正常或异常。
1. 完成、延期、跳过、取消任务后，状态和通知保持一致。
1. 关闭系统通知权限后，应用内任务列表仍可使用。
1. 杀进程或重启设备后，已保存的记录仍存在，未来提醒可重新安排。
1. 备份恢复后，鱼缸、鱼只、历史事件和照片引用完整。
1. 重复点击保存不会产生重复喂食或重复水质记录。
1. 删除/归档等危险操作有确认，错误操作不会静默丢失历史。
1. 页面支持空数据、错误、处理中和正常四类状态。

| statusChangedAt | DATETIME NULL | 状态发生时间 |
| notes | TEXT NULL | 备注 |
| createdAt / updatedAt | DATETIME | 审计时间 |

# 附录 B：开发约束

- UI 层不直接访问 Room DAO；统一通过 Repository。
- 数据库结构变化必须提供 Room Migration，禁止正式版本使用 destructive migration 丢数据。
- 统计逻辑集中在领域/数据层，避免首页、鱼只详情分别计算出不同结果。
- 所有日期与单位显示逻辑集中实现并覆盖测试。
- 提醒任务和本地通知的唯一性必须由持久化 ID 保证。
- 本阶段不引入需要 API Key 的第三方云服务；若未来接入云端服务，不得将密钥硬编码在客户端。
